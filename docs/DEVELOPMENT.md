Everything about working on the site itself. To add or fix a listing, all you
need is [CONTRIBUTING.md](../CONTRIBUTING.md).

The site is plain HTML, CSS and JavaScript: no framework, no runtime
dependencies and no build step to view it. Node 22 or newer runs the dev
server, the tests and the scripts that generate pages and feeds.

## Run it locally

```bash
git clone https://github.com/bnvac/stdnt.xyz
cd stdnt.xyz
npm run dev        # http://localhost:8000 (PORT=3000 npm run dev to change it)
npm install        # once, before running the tests
```

`npm run dev` serves `site/` the way GitHub Pages does: folders serve their
`index.html` and anything missing gets the 404 page. Nothing is cached, so
edits show on reload. You can also just open `site/index.html`.

## Commands

| Command | What it does |
|---|---|
| `npm run dev` | serve `site/` at http://localhost:8000 (`PORT=3000` to change) |
| `npm test` | data check + test suite (what CI runs on every push and PR) |
| `npm run check` | just the data check: missing fields, bad URLs, duplicates, unreadable deadlines |
| `npm run build` | refresh hackathons, cache new logos, rebuild the calendar feeds and static pages |
| `npm run build:pages` | rebuild only the feeds and static pages (no network) |
| `npm run check:links` | check every external link (slow; CI does this weekly) |
| `npm run images` | re-render share images and icons (needs Playwright, see the script header) |
| `npm run banner` | redraw the README banner with current counts (needs HarfBuzz, see the script header) |

## House rules

- **Bump the cache number.** After changing anything in `site/js/` or
  `site/css/`, bump the `?v=N` on every asset in `site/index.html` together
  (search and replace `?v=NN`), so visitors don't get a stale copy.
- **No em or en dashes.** Use plain hyphens, commas or colons.
- **Date new listings.** Give each one `added: "YYYY-MM-DD"`, the day you add
  it. It shows on the New tab and the `new/` page for six months.
- **Official links only**, and never edit generated files by hand (below).

The data check catches mismatched `?v=` numbers, dashes and malformed `added`
dates, so `npm test` fails before CI does.

## Generated files

`npm run build` makes these from the data files. The *Build and deploy site*
workflow runs it on every push to `main` and daily, and commits whatever
changed, so edit the data in `site/js/` instead:

| Path | Script | What it is |
|---|---|---|
| the page folders (`site/guides/`, `site/new/`...), `404.html`, `sitemap.xml` | `build-pages.mjs` | static pages search engines can index |
| `site/calendar/*.ics` | `build-calendar.mjs` | subscribable deadline feeds |
| `site/logos/`, `site/js/logos.js` | `build-logos.mjs` | cached favicons and brand icons |
| `site/data/hackathons.json` | `build-hackathons.mjs` | upcoming hackathons from the Hack Club API |
| `site/data/link-status.json` | `check-links.mjs` | links that failed two weekly checks in a row |

Two are rendered by hand when needed: the share images and icons
(`npm run images`, after adding a guide or editing `favicon.svg`) and
`.github/banner.svg` (`npm run banner`).

## GitHub workflows

- **Checks** (`ci.yml`) runs `npm test` on every push and pull request.
- **Build and deploy site** (`site-build.yml`) runs `npm run build`, commits
  the generated files and publishes `site/` to GitHub Pages. It runs on every
  push to `main`, daily at 06:00 UTC (the deadlines page, feeds and hackathons
  depend on the date) and on demand.
- **Link check** (`link-check.yml`) runs every Monday. A link counts as dead
  after failing two weeks in a row: it gets a "Link may be down" note on the
  site and a line in one "Broken links" issue, which closes itself once
  everything passes.

## Deploying

The *Build and deploy site* workflow publishes to GitHub Pages. One-time setup:
**Settings → Pages → Source: GitHub Actions**. Until that's set, the workflow
skips the deploy with a notice and Pages serves the repo root, where a
temporary `index.html` forwards visitors to `site/`. Delete that file and
`.nojekyll` once the source is switched.

To serve it at stdnt.xyz, add the domain under **Settings → Pages → Custom
domain** (deploys from Actions don't need a `CNAME` file), point its DNS at
GitHub Pages (`A` records for `185.199.108.153`, `185.199.109.153`,
`185.199.110.153` and `185.199.111.153`, plus a `CNAME` from `www` to
`bnvac.github.io`), then tick **Enforce HTTPS**. Canonical URLs, the sitemap
and the feeds already use `https://stdnt.xyz` (`SITE` in `scripts/lib/data.mjs`).

## Newsletter and email reminders

A static site can't send email, so both stay off until you connect a free
third-party service:

- [NEWSLETTER.md](NEWSLETTER.md): the weekly digest signup (Buttondown or
  Mailchimp). It's one variable plus a cache bump.
- [EMAIL_REMINDERS.md](EMAIL_REMINDERS.md): emailing students before their
  deadlines.

The on-site *"This week for you"* digest works without either.
